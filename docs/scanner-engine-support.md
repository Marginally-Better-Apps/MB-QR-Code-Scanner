# Scanner engine

The SwiftUI app uses AVFoundation for live frames and its preview layer. One Vision request detects every barcode symbology reported by the running OS across the full frame. That includes QR, Micro QR, Aztec, Data Matrix, PDF417, MicroPDF417, EAN, UPC, Code 128, GS1 DataBar, and other linear formats. Core Image provides a QR-only fallback if Vision fails; Simulator also uses it when Vision returns no observations for a static test image. Empty device frames do not run a second decoder.

Decoding, preview projection, and frame throttling are in `Sources/QRScannerCore/Vision`. The camera is in `native/QRScanner/Camera`: `CaptureController` owns the session and device on one serial queue, `FrameProcessor` runs Vision on its own queue, and `ScannerPreviewView` hosts the preview and gestures. Debug and Simulator builds can replace the camera with a bundled image (`DebugImageFixtureSource`); device Release builds always use the camera.

Capture starts only after camera authorization. It pauses in History and whenever the scene is inactive. `AVCaptureDevice.RotationCoordinator` keeps the preview and frames upright, including 180° landscape flips. Frames use the preview's angle, so Vision bounds map directly onto the preview. Pinch zooms. Tap focuses and exposes at a point until the scene changes, then continuous autofocus resumes. After a media services reset or another runtime error, capture restarts; other errors get one retry per start. Capture also restarts after an interruption if the session did not resume by itself.

Detection bounds stay visible through gaps shorter than 1.5 seconds. Scan acceptance uses real camera frames only. Two consecutive sightings or repeated sightings spanning 250 ms accept a scan. A two-second absence resets deduplication. Identity includes the symbology, so identical text in two formats remains two results.

Retail lookup is limited to valid EAN-8, EAN-13/UPC-A, UPC-E, ITF-14, and GS1 DataBar numbers with a valid check digit. It is user initiated and never runs on camera frames. Vision may support a format without decoding every damaged or distant instance; physical-device measurements and a larger fixture set are still required.

`swift test` decodes real pixels with macOS Vision: the bundled fixtures in four orientations, QR payload kinds, Aztec, PDF417, Code 128, EAN-13, multiple codes, and a blank frame. It also covers preview geometry and frame throttling. `scripts/test-native-qr-decoder.sh <UDID>` repeats the QR checks inside a booted Simulator with the iOS SDK, through to persisted History. Simulator 26.5's Vision does not decode the generated Aztec fixture, so the other formats are checked on macOS only. A physical camera session still needs device testing.
